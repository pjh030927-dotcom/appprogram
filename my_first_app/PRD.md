## 1. 사용자와 사용 상황

- **주제 한 문장:** 다수 기업 지원자를 위해 내 기본 스펙·경험과 기업의 인재상을 결합하여 맞춤형으로 자기소개서를 작성·수정하고 보완 방향을 제시해 주는 웹 중심 도움 앱
- **첫 사용자:** 여러 기업에 동시에 입사 원서를 제출하며, 기업별 문항과 직무 특성에 맞춰 기존 자기소개서와 활동 이력을 반복해서 정리·수정하는 신입 취업 준비생
- **사용하는 순간:** 채용 시즌에 여러 기업의 자기소개서 마감 기한(D-Day)을 확인하고, 미리 정리해 둔 본인의 스펙·경험 데이터를 바탕으로 각 기업의 자소서 항목을 실시간 글자 수에 맞춰 작성·복사·보관하려는 순간

## 2. 문제·사실·가정

- **문제 한 문장:** 기업마다 요구하는 자소서 문항과 인재상 조건이 달라 여러 기업에 동시 지원할 때 마감 관리와 매번 이력을 새로 고쳐 쓰는 과정이 번거로움

| 구분 | 내용 | 근거·한계 또는 확인 방법 |
| --- | --- | --- |
| 확인한 사실 | 기업마다 자기소개서 요구 사항과 조건이 다르고 지원할 때마다 매번 수정해야 한다. | 지인 취업 준비 경험 및 유사 서비스 비교 결과 |
| 문제에 관한 가정 | 다른 다수 기업 지원자들도 본인 이력을 매번 반복 입력하고 항목별 글자 수를 맞추는 과정에서 피로감을 겪고 있을 것이다. | 주변 취업 준비생 지인에게 자소서 작성 시 가장 번거로운 부분을 질문하여 확인 |
| 해결 효과의 가정 | 기본 스펙을 앱에 저장해 두고 기업별 상세 자소서 화면에서 스펙 불러오기·실시간 글자 수 확인·자동 저장·복사/내보내기 및 후속 AI 부분 수정을 제공하면 작성 효율이 높아질 것이다. | 대시보드, 스펙 보관함, 자소서 상세 에디터 및 저장·복사·내보내기 기능을 구현해 동작을 확인했으며, AI 부분 수정은 후속 단계에서 검증 예정 |

## 3. 핵심 가치

- **사용자가 얻을 결과:** 여러 기업의 마감일과 자소서를 한곳에서 파악해 일정 누락을 줄이고, 한 번 등록한 학력·자격증·직무 경험을 각 기업 자소서로 불러와 실시간 글자 수와 자동 저장 환경에서 안전하게 작성한 뒤 바로 복사하거나 파일로 내보낼 수 있다.
- **기능과의 연결:**
  - **자소서 대시보드:** 지원 기업과 마감일을 등록·삭제하고 D-Day를 자동 계산해 작성 우선순위를 정한다.
  - **내 기본 스펙·경험 보관함:** 학력·자격증·직무 경험을 양식에 맞춰 1회 등록해 영구 보관하고 카테고리별로 조회한다.
  - **기업별 자소서 상세 에디터:** 기본 7개 항목과 사용자 추가 문항을 작성하며 스펙 불러오기, 목표 글자 수 초과 경고, 자동 저장(120초)·미저장 이탈 방지, 원클릭 복사 및 `.txt` 파일 내보내기를 통해 실사용 작성 흐름을 완결한다.

## 4. 기능과 현재 구현 범위

- **앱 전체의 핵심 기능 후보:**
  1. 지원 기업별 마감 D-Day 대시보드 (**구현 완료**)
  2. 내 기본 스펙·경험 정리 보관함 — 학력/자격증/직무 경험 (**구현 완료**)
  3. 기업별 자소서 상세 에디터 — 기본 7개 항목 + 직접 추가 문항 + 스펙 불러오기 + 실시간 글자 수/목표 글자 수 초과 경고 (**구현 완료**)
  4. 작성 편의 및 보호 기능 — 자동 저장(120초 설정), 미저장 이탈 방지(`PopScope`), 문항별 원클릭 복사, `.txt` 파일 내보내기 (**구현 완료**)
  5. 웹 URL 라우팅 (`go_router`) — (**부분 적용 / 주소창 경로 반영 수정 보류**)
  6. 기업 인재상 키워드 기반 사실 중심 AI 부분 수정 및 경력 로드맵 (**미구현 — 목업 구상 완료, 후속 작업**)
- **후속 작업 및 보류 항목과 이유:**
  - **웹 URL 라우팅 주소창 경로 반영 (`context.go` + 중첩 라우트 전환):** `go_router` 적용 후 `context.push` 사용 시 브라우저 주소창이 `localhost`로 유지되는 현상을 확인했으나, 현재 주차에서는 추가 수정을 보류함
  - **AI API 연동 맞춤형 부분 수정 및 경력 로드맵:** 자소서 작성·저장·내보내기 구조를 우선 안정화한 뒤 AI API 연동 및 백엔드 프록시 검토를 진행 예정
  - **채용 공고 불러오기 및 링크 기반 인재상 자동 추출:** 외부 취업 포털 크롤링 시 백엔드 서버 구축이 필요하고 AI 무료 토큰 소모가 심화될 우려가 있어 제외
- **데이터 출처:** 사용자가 앱 내 입력 양식 및 다이얼로그를 통해 직접 입력하는 데이터
- **저장·외부 연동의 현재 범위:** `provider` 전역 상태 관리 + `shared_preferences` 기반 로컬 영구 저장 구현 완료 (외부 서버·클라우드 DB·AI API 미연동)

## 5. 화면별 요구사항

| 요구 번호 | 사용자가 볼 정보 | 입력·선택·버튼 | 행동 후 반응 |
| --- | --- | --- | --- |
| R1 | 상단 앱바 타이틀, '공고 보기', '내 스펙·경험 입력(건수)' 버튼 | '공고 보기' 클릭 / '내 스펙·경험 입력' 클릭 | '공고 보기'는 추후 확장 안내 스낵바 표시 / '내 스펙·경험 입력'은 스펙 정리 화면으로 이동 |
| R2 | 상단 지원·스펙 현황 요약 및 빈 상태 안내 화면 | 초기 진입 시 별도 입력 없음 | 작성 중인 자소서가 없으면 중앙에 빈 상태 안내 문구 표시 |
| R3 | 새 지원 기업 추가 다이얼로그 및 D-Day 카드 목록 | 기업명 입력·달력 마감일 선택 후 '저장' / 삭제 아이콘 클릭 | 기업명·마감일·D-Day가 포함된 카드가 생성 및 로컬 저장 / 삭제 확인 팝업 후 제거 |
| R4 | 다이얼로그 및 입력 양식의 빈 값 방어 | 필수 명칭을 비운 채 '저장' 클릭 | 빈 항목이 등록되지 않고 입력칸 하단에 오류 문구 표시 |
| R5 | 내 기본 스펙·경험 정리 화면 (학력·자격증·직무 경험) | 카테고리 칩 선택, 양식 및 달력(`showDatePicker`) 날짜 입력 후 저장 / 필터 칩 선택 | 카테고리에 맞는 라벨로 전환, 로컬 영구 저장 및 카테고리별 필터 조회·삭제 |
| R6 | 기업별 자소서 상세 에디터 진입 | 대시보드에서 특정 기업 카드 클릭 | 해당 기업의 자소서 상세 화면으로 이동하며 기존 저장 데이터 로드 |
| R7 | 동적 추가 입력 항목 (직무 경험·대내외 활동·어학·자격/면허·수상) | 각 영역의 추가 버튼(`+ 활동 추가` 등) 클릭 후 세부 항목 입력 | 경험·활동(활동명, 상세설명), 어학·자격/면허(종류, 등급, 점수, 자격번호), 수상(수상내용, 시상단체, 수상일자 달력, 상세설명) 카드 동적 생성·삭제 |
| R8 | 자기소개·지원동기 작성 및 실시간 글자 수 표시 | 자기소개·지원동기·상세설명 입력 및 '저장하기' 클릭 | 입력 즉시 공백 포함/제외 글자 수가 실시간 갱신되며 로컬 저장소에 영구 반영 |
| R9 | 내 스펙 보관함 연동 불러오기 팝업 | 상단 '스펙 불러오기' 클릭 후 항목 체크 및 반영 영역 지정 | 선택한 스펙이 지정한 자소서 영역 카드로 복사됨 |
| R10 | 문항별 목표 글자 수 및 초과 경고 | 각 문항 하단 '목표 글자 수' 숫자 입력 후 본문 작성 | 목표 글자 수 대비 현재 글자 수 표시, 초과 시 빨간색 경고 및 초과 글자 수 안내 |
| R11 | 사용자 직접 추가 문항 영역 | 하단 '+ 문항 추가' 클릭 후 제목·답변·목표 글자 수 입력 | 기업별 특수 문항 카드 동적 추가·삭제 및 영구 저장 |
| R12 | 자동 저장(120초) 및 미저장 이탈 방지 | 내용 수정 후 대기 / 미저장 상태에서 뒤로 가기 클릭 | 120초 기준으로 자동 저장 실행 및 상단 상태 배지 갱신 / 미저장 이탈 시 확인 팝업(`PopScope`) 노출 |
| R13 | 문항별 원클릭 복사 및 `.txt` 파일 내보내기 | 문항 하단 '복사' 버튼 클릭 / 상단 'TXT 내보내기' 클릭 | 해당 문항 텍스트 클립보드 복사 / 전체 자소서가 정리된 `기업명_자소서.txt` 파일 다운로드 |
| R14 | 웹 URL 라우팅 (`/`, `/specs`, `/resume/:id`) | 화면 이동 및 브라우저 새로고침(`F5`) | *(보류)* `go_router` 기본 연결은 적용했으나, 주소창 경로 반영을 위한 중첩 라우트·`context.go()` 전환은 미실행 상태 |
