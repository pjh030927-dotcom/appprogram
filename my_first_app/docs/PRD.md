# [앱 이름] PRD — 제품 요구사항 문서

9주차에 정한 주제를 구체화합니다. 대괄호를 실제 내용으로 바꾸고 한 페이지 안팎에서 시작합니다. 아직 모르는 내용은 미정으로 남깁니다. 프로젝트를 만든 뒤 docs/PRD.md에 보관할 수 있습니다.

## 1. 사용자와 사용 상황

- 주제 한 문장: [다수 기업 지원자를 위해 내 기본 경험과 기업의 인재상을 결합하여 맞춤형으로 자기소개서를 수정해 주고 보완 방안을 제시해 주는 데스크톱 웹 중심 도움 앱]
- 첫 사용자: [여러 기업에 동시에 입사 원서를 제출하며, 기업별 문항과 직무 특성에 맞춰 기존 자기소개서를 반복해서 수정하는 신입 취업 준비생]
- 사용하는 순간: [채용 시즌에 데스크톱 환경에서 여러 기업의 자기소개서 마감 기한을 확인하고, 미리 정리해 둔 본인의 경험 데이터를 바탕으로 특정 기업의 인재상에 맞게 자기소개서 문장을 다듬으려는 순간]

## 2. 문제·사실·가정

- 문제 한 문장: [기업마다 요구하는 자소서 문항과 인재상 조건이 달라 여러 기업에 동시 지원할 때 매번 글을 새로 고쳐야 함]

| 구분 | 내용 | 근거·한계 또는 확인 방법 |
| --- | --- | --- |
| 확인한 사실 | [기업마다 자기소개서 요구 사항과 조건이 다르고 지원할 때 마다 매번 수정해야한다.] | [지인 취업 준비 경험 및 유사 서비스 비교 결과] |
| 문제에 관한 가정 | [다른 다수 기업 지원자들도 본인 이력을 매번 반복 입력하는 과정에서 피로감을 겪고 있을 것이다.] | [주변 취업준비생 지인에게 자소서 작성시 가장 번거로운 부분을 질문하여 확인한다.] |
| 해결 효과의 가정 | [내 기본 경험을 앱에 저장해두고 원하는 문장 연역만 선택해 기업 인재상 키워드와 결합하여 AI 수정을 요청 및 비교할 수 있다] | [첫 화면 에서 기업 관리 흐름을 먼저 확인하고 후속 주차에 경험 저장 및 AI 부분 수정 비교 화면을 구현해 실제 자소서 1편을 수정해보며 검증] |

AI가 만든 수치와 예시를 조사 사실로 적지 않습니다. 본인의 경험도 다른 사용자 전체에 해당하는 사실로 확대하지 않습니다.

## 3. 핵심 가치

- 사용자가 얻을 결과: [여러 기업의 마감일과 자소서를 한곳에서 파악하여 관리 부담을 줄이고, 매번 이력을 새로 입력할 필요 없이 각 기업이 원하는 인재상에 맞춰 본인의 부족한 문장을 빠르게 채워 넣을 수 있다.]
- 기능과의 연결: [첫 화면 대시보드에서 지원 기업과 마감일을 등록 및 확인하여 우선순위를 정한다. '내 기본 경험 보관함'에 본인의 핵심 경험을 미리 기록해둔다.]

목록·버튼 같은 기능 이름만 쓰지 말고, 그 기능으로 무엇이 나아지는지 설명합니다.

## 4. 기능과 이번 구현 범위

- 앱 전체의 핵심 기능 후보: [첫 화면 대시보드, 내 기본 경험 보관함 등록 및 관리, 기업 인재상 키워드 수동 입력 및 부분 수정 요청]
- 오늘 구현할 첫 화면과 행동: [상단 앱바에 '공고보기' 버튼관 '내 기본 경험 정리하기 버튼을 배치하고 클릭 시 상태 안내 표시, 메인 영역에 '작성 중인 자소서 목록' 그리드 뷰 및 빈 상태 안내 문구 표시]
- 후속 작업으로 남길 기능과 이유: [내 경험 보관함 상세 화면 및 자소서 에디터 AI 부분 수정 : 첫 화면 대시보드 뼈대와 목록 상태 관리를 먼저 완성한 뒤 이후 단계적으로 연결, 채용 공고 불러오기 및 링크 기반 인재상 자동 추출 : 외부 취업 포털 크롤링 시 백엔드 서버 구축이 필요하고 AI 무료 토큰 소모가 심화될 우려가 있어 제외]
- 데이터 출처: [사용자가 다이얼로그 입력창을 통해 직접 입력하는 데이터]
- 저장·외부 연동의 현재 범위: [메모리 동작 구현 완료]

## 5. 첫 화면

| 요구 번호 | 사용자가 볼 정보 | 입력·선택·버튼 | 행동 후 반응 |
| --- | --- | --- | --- |
| R1 | [상단 앱바 타이틀 및 상단 기능 이동 버튼 2개] | ['공고 보기' 버튼, '내 기본 경험 정리하기' 버튼 클릭] | [화면 하단에 각각 '공고 보기 기능은 준비 중입니다.', '내 경험 정리 화면으로 이동합니다.' 스낵바 알림이 표시됨] |
| R2 | [작성 중인 자소서가 없을 때의 빈 상태 안내 화면] | [별도 입력 없음] | [화면 중앙에 '작성 중인 자소서가 없습니다. 새 자소서를 추가해 주세요.' 안내 문구가 표시됨] |
| R2 | [새 지원 기업 추가 팝업 다이얼로그] | ['새 자소서 추가' 버튼 클릭 후 기업명 텍스트 입력, 마감일 버튼 클릭해 달력에서 날짜 선택 후 저장] | [다이얼로그가 닫히고, 입력 한 기업명 마감일 계산된 남은 일수가 담긴 카드가 그리드 목록에 추가] |
| R2 | [다이얼로그 내 잘못된 입력  방어] | [기업명을 입력하지 않고 공백 상태에서 '저장' 버튼 클릭] | [목록에 빈 카드가 추가되지 않고 다이얼로그가 닫히지 않은 채 입력 대기 상태를 유지함] |

화면 구상: [데스크톤 웹 화면 상단에 타이틀과 주요 이동 버튼을 배치하고 본문 상단 우측에 '새 자소서 추가' 버튼을 두며, 본문 중앙에는 등록된 기업별 자솟 ㅓ카드를 격자 형태로 나열하는 구조]

빈 데이터나 잘못된 입력 등 해당하는 조건: [초기 실행 시 목록 리스트가 비어 있으면 빈 화면 대신 중앙 안내 문구를 노출한다. 새 기업 추가시 기업명입력란을 검사하여 빈 문자열일 때는 저장 동작이 실행되지 않도록 막는다.]
