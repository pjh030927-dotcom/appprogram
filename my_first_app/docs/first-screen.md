# 첫 화면 구상과 확인 기록

PRD의 요구를 화면으로 옮기고, 실제 실행 결과를 기록합니다. 기존 문서를 사용해도 같은 내용이 드러나면 됩니다.

## 화면 구상

- 앱 이름·주제: [자소서 작성 도움 및 AI 맞춤형 수정 도움 앱]
- 화면의 핵심 사용자 행동: [지원할 기업의 자소서 항목을 다이얼로그로 등록하여 대시보드에서 D-day와 함께 한눈에 확인하고, 경험 정리 및 공고 보기 메뉴로 진입하는 행동]
- 위에서 아래로 보여 줄 정보: [상단 앱바: 좌측에 '자소서 대시보드' 제목, 우측에 '공고 보기' 텍스트 버튼과 '내 기본 경험 정리하기' 버튼
본문 헤더 영역: 좌측에 '작성 중인 자소서 목록' 섹션 제목, 우측에 '새 자소서 추가' 버튼
본문 메인 영역: 등록된 자소서가 없을 때: 중앙에 '작성 중인 자소서가 없습니다. 새 자소서를 추가해 주세요.' 안내 문구, 등록된 자소서가 있을 때: 반응형 격자형태로 각 기업의 이름, 우측 상단 붉은색 D-day 태그, 하단 마감일 표시]
- 입력·선택·버튼과 그 뒤의 반응: [공고 보기 클릭: 하단에 '공고 보기 기능은 준비중 입니다.' 스낵바 표시
내 기본 경험 정리하기 클릭: 하단에 '내 경험 정리 화면으로 이동합니다. 스낵바 표시]
- 사용 전·빈 데이터·잘못된 입력 등 해당하는 상태: [사용전 조건으로 확인하여 빈 그리드 대신 안내 텍스트를 중앙에 렌더링함.
잘못된 입력: 다이얼로그에서 기업명을 비워둔 채 저장을 누르면 if 조건에 의해 리스트 추가 및 팝업 닫기가 실행되지 않음]
- PRD 요구 번호와 화면 요소의 연결: [R1 = 상단 앱바내 버튼 2개
R2 = 본문 _resumeList.isEmpty 분기 처리의 Center(child: Text(...))

R4 = 다이얼로그 '저장' 버튼 내부의 if 조건문]
