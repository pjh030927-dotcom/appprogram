# 프롬프트 엔지니어링 실습 — 같은 공지 기능의 요청 비교

코드와 완료 기준을 고정하고 요청의 표현을 비교합니다.
두 개의 새 대화를 열고 같은 모델을 선택하세요.
도구 접근이 가능한 AI라면 첫 비교는 파일 변경과 명령 실행을 끈 채 답변만 받습니다.
각 대화에 아래 공통 자료와 수정 전 `starter_main.dart` 전문을 먼저 넣습니다.
A의 답변을 B에게 제공하지 않습니다.

## 교재 개념을 답변 검토에 사용하기

답변에서 Future를 새 스레드와 같은 것으로 설명하는지 확인하세요.
await가 현재 함수의 후속 처리를 기다리게 한다는 뜻을 유지해야 합니다.
setState의 콜백은 동기적인 상태 변경만 담고 mounted 검사는 await 뒤에 유지합니다.
공지의 모의 대기를 불필요한 isolate나 외부 API로 바꾸지 않습니다.
이 개념 검토도 A와 B에 같은 기준으로 적용합니다.

## 공통 자료

```text
Flutter 공지 앱의 loadNotice TODO를 완성하는 작업입니다.
수정 전 starter_main.dart 전체 코드는 이 메시지 아래에 붙입니다.
AC1: 요청 직후 로딩 표시, 버튼 잠금, 이전 결과와 오류 제거.
AC2: 실패 OFF이면 1초 뒤 공지 본문 표시, 로딩 종료, 버튼 활성화.
AC3: 실패 ON이면 실패 안내와 다시 시도 버튼 표시, 로딩 종료.
AC4: 실패 OFF로 바꿔 재시도하면 성공하고 이전 오류가 사라짐.
AC5: 로딩 중 중복 클릭에도 요청 횟수가 늘지 않음.
서비스의 지연과 반환값은 제공한 코드의 계약을 사용합니다.
```

## 요청 A

```text
첨부한 공지 앱에서 loadNotice의 TODO를 완성해 줘.
```

## 요청 B

```text
Flutter 학습 도우미로서 첨부한 같은 코드의 loadNotice TODO만 구현해 줘.
공통 자료의 AC1–AC5를 지켜 줘.
fetchNotice, 화면 구조, 1초 지연, 오류 ID는 유지해 줘.
새 패키지, 외부 API, 로그인, 저장 기능은 추가하지 마.
setState 안에서 await하지 말고 await 뒤의 mounted 검사를 유지해 줘.
답변은 변경 함수 전체 → 변경 이유 → AC별 확인 순서 → 실제 실행 기록 순서로 써 줘.
도구를 실행하지 않았다면 검증은 미실행이라고 표시해 줘.
```

## 비교와 적용

1. 모델 표시 이름과 사용 시각을 적습니다. 공통 코드의 사본을 보존합니다.
2. 원래 코드에서 각 답변이 무엇을 바꾸는지 비교합니다.
3. 범위, AC, 설명, 실행 주장의 근거를 표에 기록합니다.
4. 선택한 답변을 검토하고 함수에 적용합니다. 자신의 말로 await 전후를 설명합니다.
5. 가능하면 A/B를 별도 사본에 적용해 각각 실행합니다. 실행하지 않은 쪽은 미검증으로 남깁니다.

| 항목 | A의 실제 결과 | B의 실제 결과 | 근거 |
|---|---|---|---|
| TODO 외 변경·새 패키지 | 변경X | 변경X | starter_main.dart 의 TODO 위치 |
| AC1–AC5 | 통과 | 통과 | evidence 증거 파일 참조 |
| await와 오류 설명 | 설명하지 않음 | 설명함 | 내부에서 비동기 작업(await)을 수행하면 화면 업데이트 타이밍이 어긋나거나 프레임워크에 오류를 일으킬 수 있습니다. |
| 미실행의 정확한 표시 | 표시X | 표시O | 도구 실행 여부: 미실행 (AI 환경에서 직접 테스트 코드를 실행하지 않음) |

선택한 요청: B / 선택 이유: 원하는 결과에 맞춰 답변을 해주기 때문이다.

한 번의 결과로 모든 AI의 성능을 일반화하지 않습니다.
더 긴 답변을 더 정확한 답변으로 판단하지 않습니다.

## 선택 활동: 예시와 오류 피드백

예시를 추가할 때는 `실패 ON + 요청 → loading → failure → 다시 시도`처럼 입력과 기대 출력을 짝지어 적습니다.
첫 비교를 마친 뒤 시도하고 A/B 공통 조건을 뒤늦게 바꾸지 않습니다.

실제 실패가 있다면 다음 요청을 자신의 관측으로 채웁니다.

```text
기대 행동: 실패 ON + 요청 -> loading -> failure -> 다시 시도
실제 행동과 재현 순서: 요청 시 로딩이 끝나지 않음
현재 loadNotice 코드: setState(() {
        _error = '공지사항을 불러오는 데 실패했습니다.';
      });
실제 오류 로그:_status = LoadStatus.failure; 부분이 빠짐
허용 변경: 관측된 오류 분기만 수정. 서비스 계약과 AC 유지.
출력: 수정 함수, 원인 근거, 재확인할 AC, 미실행 항목.
```

실패가 없으면 `실패 없음`이라고 적습니다. 연습용 가상 오류를 실제 실행 기록으로 제출하지 않습니다.
